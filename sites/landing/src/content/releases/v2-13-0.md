## What's New in v2.13.0

GraphQL change classification gains the same API Kind model as REST. Agents can authenticate with a PAT, and operators get a Builds API plus YAML config for the linter and agents-backend.

### GraphQL API Kind
- `no-bwc` and `experimental` apiKind on GraphQL operations in API Changes
- Same treatment as REST: those operations do not fail a compatibility gate the way a breaking change on a stable API would

### Agents and admin
- PAT authentication strategy on agents-backend
- Admin API for build details
- Dashboard reference cards link to the package versions they include
- Client IP headers forwarded to the backend for access logs

### Publish and search
- Previous-version status is validated on publication (feature-flagged)
- Global search honors the API-type filter
- Large publishing error lists open in a popup instead of overflowing the page

### Ops
- Agents-backend and API Linter read `config.yaml` instead of a long env-var list
- Deprecated search scopes removed from the processor, consumer, and Portal

### Fixes
- Changelog no longer drops colliding operations
- GraphQL input-object and enum default values print correctly
- OpenAPI operation-group export omits unused tags
- Dashboard comparisons honor excluded references; comparison document IDs stay stable across migrations
